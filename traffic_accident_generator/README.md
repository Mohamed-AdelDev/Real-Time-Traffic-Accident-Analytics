# Synthetic Traffic Accident Dataset Generator

> **ALL DATA PRODUCED BY THIS PROJECT IS SYNTHETIC.** Every accident, vehicle and casualty is
> generated by probability rules for testing and demonstrating a Big Data pipeline
> (Kafka → NiFi → Spark Structured Streaming → PostgreSQL → Power BI / Streamlit).
> The records are **not** real reported accidents and are **not** real-world observations.
> Road names, areas and coordinates are plausible labels only.

## 2. Installation

Requires Python 3.9+.

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
```

Faker is not needed: every value comes from realistic lookup tables.

## 3. Configure the number of accidents

Option A – edit `config.py`:

```python
NUM_ACCIDENTS = 100_000      # use 10_000 for a quick test
RANDOM_SEED = 42             # same seed = identical dataset
START_DATE / END_DATE        # default: 2023-01-01 .. 2024-12-31 (two full years)
```

Option B – command line (overrides `config.py`):

```bash
python generate_traffic_data.py --num-accidents 10000
python generate_traffic_data.py -n 50000 --seed 7 --output-dir my_dataset
```

## 4. Run

```bash
python generate_traffic_data.py
```

100,000 accidents take about 20 seconds. The script generates the data, prints the validation
report, and writes the folder `traffic_accident_dataset/`:

```
Accidents.csv            one row per accident (41 columns)
Vehicles.csv             one row per vehicle   (20 columns)
Casualties.csv           one row per casualty  (11 columns)
data_dictionary.csv      every column: type + meaning
generation_summary.txt   totals, distributions, date range, missing values, validation results
```

The script exits with a non-zero code if any validation check fails.

## 5. Dataset structure

```
Accidents (accident_id PK)
   ├── 1..n  Vehicles   (vehicle_id PK, accident_id FK)
   └── 1..n  Casualties (casualty_id PK, accident_id FK, vehicle_id FK – NULL for pedestrians)
```

* **Accidents.csv** – identification, location, severity, weather, road conditions and 8 boolean
  contributing factors (several can be `True` together) plus `primary_cause`.
* **Vehicles.csv** – vehicle, driver and safety-equipment details. `vehicle_reference` is 1, 2, 3 …
  inside each accident.
* **Casualties.csv** – injured people: drivers, passengers, pedestrians, cyclists, motorcyclists.

Conventions worth knowing:

* **Empty cell = NULL.** `seatbelt_used` is empty for motorcycles, bicycles and buses;
  `helmet_used` is empty for everything except motorcycles/bicycles; `engine_capacity_cc` is empty
  for bicycles; `vehicle_id` is empty for pedestrians. A small share of weather values and driver
  details are empty to mimic sensor gaps and unknown drivers (hit-and-run).
* Categories such as `No Junction`, `No Hazard` and `No Damage` are real **text values**, not NULLs.
* `speed_limit` is in **km/h** (rounded UK limits 32/48/64/80/96/112) so it compares directly with
  `vehicle_speed_kmh`.
* Booleans are written as `True` / `False` (PostgreSQL `COPY` accepts them).
* IDs are stable and sequential in **chronological order** (`ACC0000001`, `VEH00000001`,
  `CAS00000001`), so replaying by ID replays by time.

## 6. How realism is built in

* **Time** – weekday rush-hour peaks (07–09, 16–18), weekend afternoon/late-night profile, Friday
  busiest, darker months busier, a mild year-over-year decline, two full years.
* **Weather ↔ road** – daily weather per city; fog → visibility < 1 km; rain → wet roads; icy only
  ≤ 3 °C; snow only Nov–Apr; bad-weather days create more accidents.
* **Location** – 10 UK cities with named areas, rural outskirts and 2 tight **hotspot junctions**
  per city for high-risk-location analysis.
* **Severity** – a risk score (speeding, drink, dark/unlit roads, rural roads, speed, pedestrians,
  motorcycles, missing helmets/seatbelts …) gives ≈ 79% Slight / 18% Serious / 2.6% Fatal.
  Accident severity always equals the worst casualty injury, but casualties differ from each other.
* **Vehicles/drivers** – type mix depends on place, season, hour and weather; drivers respect
  minimum ages (e.g. trucks ≥ 21), experience ≤ age, make/model/engine come from one catalogue.

## 7. Preparing the Kafka producer

`event_builder_example.py` shows the pattern for the **separate** producer:

```bash
python event_builder_example.py --count 1            # print one complete JSON event
python event_builder_example.py --count 5 --delay 1  # simulate 1 event per second
```

Each event contains `accident`, `location`, `weather`, `road_conditions`, `contributing_factors`,
`vehicles[]`, `casualties[]` and the flag `"is_synthetic": true`. In your producer, replace the
`print` with `producer.send(topic, value=event)` and set the delay you need.

## 8. Limitations

Coordinates are drawn around city areas and may occasionally fall on water or open land – they are
meant for maps/heatmaps, not navigation. Fatal accidents are intentionally a little more frequent
than in real statistics so that small test datasets still contain enough of them for analytics.
